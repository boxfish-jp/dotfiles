# Review Range

レビューに渡す範囲は、コミットしていないファイルから決める。レビュアーはコンテキストを引き継がないので、渡した範囲だけがレビューの世界になる。渡し漏れは「問題なし」に見え、渡しすぎは無関係な指摘になる。

## 対象

- HEAD との差分（ステージ済み＋未ステージ）と、未追跡ファイル。
- コミット済みの変更は除く。レビュー済みか、別の変更として扱う。

## 手順

1. 実装を始める前に基準を控える。`git status --porcelain` と `git diff HEAD` を /tmp に保存する。
2. 実装が終わったら、`git status --porcelain` と `git diff HEAD` を取り直して基準と比べる。基準に無いパスとハンクが今回の編集。
3. 対象の差分を取る。
   - 追跡済み: `git diff HEAD -- <paths>`（ステージ済みも含む）
   - 未追跡: `git ls-files --others --exclude-standard -- <paths>` で一覧を出し、中身はファイル全文を渡す
4. 基準から変わらず未コミットのまま残っている変更は、今回の編集ではない。除く。

## 今回の編集以外が混ざる場合

- ファイル単位で混ざる: 除くパスを列挙する。
- 同一ファイル内でハンクが混ざる: 基準の diff にあったハンクを除く。関数名か行範囲で名指しする。
- 迷ったら範囲を広げず、除くものとして明示する。黙って範囲を削らない。
- 実装が触ったファイルが除かれていないか確認する。

## レビュアーに渡すもの

- 対象の差分、または対象ファイルの内容
- 除く部分の一覧と、除いた理由
- ベースコミット（`git rev-parse HEAD`）と、作業ツリーに未コミット変更が残っている事実

## 依頼文の形

```
対象: コミットしていないファイル。ただし以下を除く。
- <path>（今回の編集ではない）
- <path>: <関数名か行範囲>（同上）
ベース: <commit>
```

## 注意

- 未追跡ファイルは `git diff` に出ない。新規ファイルの渡し漏れが最も多い。
- diff に現れない前提（設定値、既存の設計判断、実行したテスト）は、必要なら本文で補足する。補足しないものはレビュアーには存在しない。
