# Issue Style

本文は `## 症状` と `## 場所` の2節だけ。

- `## 症状`: 観測した事実。何が、どの条件で起きるか。件数・時刻・ID はそのまま書く。
- `## 場所`: 症状が現れるファイルと関数・節。特定できなければ省略する。
- タイトル: 症状を1行。修正案・優先度を入れない。
- 行番号は使わない（リファクタで壊れる）。
- テンプレートがある場合は、その見出しに合わせて症状と場所だけを埋める。

書かないもの: 影響、期待する振る舞い・修正案、原因、テスト、前提、優先度、ラベル。判断はトリアージと会話で行う。ユーザーが明示した場合だけ従う。

## 例

良い:

```markdown
## 症状

接続後、データ送信中に受信ループが閉じたセッションでは、`outbound` に `NOT_ATTEMPTED` の行が残らない。90回実験の接続済み 7,245 セッションのうち、193 で `outbound` が `manifestKeys` より少なく、27 で空だった。

## 場所

- `NearbySessionHandler.run`
- `NearbySessionHandler._sendSide`
```

悪い:

```markdown
## 症状
...
## 影響
解析の分母がずれる。
## 期待する振る舞い
build 時に補完する。
## テスト
...
## 前提
...
優先度: Low
```

観測と判断が混ざり、何が観測されたか読めなくなる。
